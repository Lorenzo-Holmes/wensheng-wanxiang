# Gemini MCP 纹路生成专项审查

- 审查方式：`mcp__gemini__ask_gemini`
- 推理强度：High
- 日期：2026-08-30

## Gemini 的核心判断

旧生成器的问题不是配色，而是生成范式错误：它把用户笔迹压缩成少量标量，再由 `motifPositions` 排列坐标并反复盖印独立图元，因此画面像 UI 图标阵列，纹样之间没有连续气脉。

Gemini 推荐改成“参数化脊线与切线萌发系统”：

1. 对用户笔迹做 Chaikin 平滑和弧长等距重采样。
2. 计算每个采样点的切线、法线、曲率与相对主弦偏移。
3. 从同一条手势骨架派生镜像、旋转、二方连续、四方连续与放射结构。
4. 云雷、缠枝莲、莲瓣、团花和如意云分别沿骨架连续展开，不再贴独立图标。
5. 删除虚线圆、同心辅助线、重复手势回声和工程网格。

## 已落实到代码

- 新增 `resampleGestureBackbone`：手势平滑、弧长重采样、切法线和曲率计算。
- 新增 `deriveStructureSkeletons`：五种结构均由骨架派生。
- 新增 `yunleiRibbonPath`：沿骨架生成连续回纹带。
- 新增藤蔓、叶片、花瓣包络、团花旋臂与如意云头渲染器。
- `drawPatternToCanvas` 已切换到 `renderContinuousPattern`，不再调用 `motifPositions` 生成主作品。
- 生长动画继续使用同一骨架的进度截断与水墨揭示。
- 修复 Seed 字符表不足 32 位导致极少数 Seed 出现 `undefined` 的问题，同时兼容既有 Seed。

## Gemini 建议的验收原则

- 主纹连续路径占主要几何长度的 75% 以上。
- 手势应决定主轴、曲率、旋向、疏密和分支位置。
- 海报留白控制在约 30%–42%。
- 主脉、侧枝、衬线线宽层级约为 4:2:1。
- 移动端单帧目标低于 12ms，避免 Long Task。
